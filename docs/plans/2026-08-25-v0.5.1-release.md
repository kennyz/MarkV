# MarkV 0.5.1 Release Implementation Plan

> **For Claude:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task.

**Goal:** Make new documents empty by default, add the supplied interface screenshot to the English README, and publish source plus a verified arm64 DMG as GitHub release `v0.5.1`.

**Architecture:** `AppModel` exposes a testable empty-document creation method used by the New command and sidebar action. The provided PNG is copied into `docs/images` and referenced by a repository-relative README image. Existing uncommitted 0.5.x file actions, image import, and local image rendering fixes ship in the same release.

**Tech Stack:** Swift 6, SwiftUI, Swift Package Manager, Git, GitHub CLI, `hdiutil`, macOS code signing.

---

### Task 1: Empty new documents

**Files:**
- Modify: `Sources/Markv/AppModel.swift`
- Modify: `Sources/Markv/ContentView.swift`
- Modify: `Sources/Markv/MarkvApp.swift`
- Modify: `Sources/Markv/Localization.swift`
- Test: `Tests/MarkvTests/AppModelTests.swift`

**Steps:**
1. Add a direct `createEmptyDocument(at:)` path that writes an empty UTF-8 Markdown file and opens it.
2. Replace all default New actions and labels that mention the starter template.
3. Test zero-byte content, current file state, directory list, and recent files.

### Task 2: README screenshot

**Files:**
- Create: `docs/images/markv-interface.png`
- Modify: `README.md`

**Steps:**
1. Copy the user-supplied PNG without modifying its content.
2. Verify dimensions and PNG integrity.
3. Add an English screenshot section near the README introduction with descriptive alt text.
4. Update the New shortcut description to state that it creates an empty document.

### Task 3: Verification and DMG

**Steps:**
1. Run all Swift tests and require a clean pass.
2. Build `dist/Markv.app`, validate Info.plist, and verify the signature.
3. Build `release/MarkV-0.5.1-macOS-arm64.dmg` with Markv.app and an Applications link.
4. Mount read-only, verify contents, version, and signature, detach, and calculate SHA-256.

### Task 4: GitHub publication

**Steps:**
1. Review the complete diff and scan for secrets, local documents, build caches, and oversized unintended files.
2. Stage source, tests, docs, README, license metadata, and the screenshot; keep app/DMG artifacts ignored.
3. Commit the 0.5.1 changes and push `main` to `kennyz/MarkV`.
4. Create public release `v0.5.1` with English notes and the arm64 DMG.
5. Verify public repository state, release status, asset size, digest, and download URL using the GitHub API.
